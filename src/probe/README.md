# 模型实测

`probe` 独立于目录同步，重新读取当前供应商的模型列表和凭据，以有界并发逐个发出非流式 Responses 请求。每个文本模型先回答固定文本，再返回固定函数名及 JSON 参数；不会执行函数，也不会启动代理任务。

成功必须包含 `status: completed` 和正确文本/函数参数，HTTP 200、空输出、失败事件、错误参数均不算通过。专用媒体/向量模型标记跳过；明确的网关换模响应头单独标记 `fallback`，响应体或选中模型头报告不同模型时标记 `different_model`。具体模型在任意一次成功响应中缺失 `model` 时标记 `unverified_identity`，匹配的请求/选中模型头不足以验证身份。`auto` 为路由别名，记录实际响应模型并按完整请求是否通过判定。无换模证据时不能证明供应商内部没有别名或换模。

结果只记录模型 ID、时间、耗时、HTTP 状态及固定错误码，不保存提示词、响应正文或凭据。HTTP 错误体最多读取 64 KiB，只保留最多 64 字符且语法受限的机器代码/type，并排除当前凭据值；不保留 message。供应商 ID、完整端点和请求头共同生成绑定指纹，每个指纹使用独立原子结果文件及锁。每完成一个模型写一次，保留中断前进度；选择部分模型时保留该供应商其他模型的历史时间戳，`counts` 只统计本次选择。单个 worker 意外失败时等待其余有界任务结束，结果保持 `complete: false`。

同一绑定的完整模型结果默认冷却七天，成功、失败、超时和换模结果均复用；`--force` 显式覆盖冷却。时间从该模型最后一个请求完成时算起，兼容旧报告的请求时间与耗时，不因重复查看报告延长或缩短。`reusedCount`、`probedCount`、`reusedIds` 与每项 `nextProbeAt` 说明本次是否产生推理请求及下次到期时间。总任务中断时仍复用已完成模型；缺少文本或工具结果的未完成项重测。媒体等跳过项每次只重判元数据，不发推理请求。

提示词与函数描述保持简短，仍要求固定文本和一个携带固定字符串参数的函数调用。明确支持 reasoning `none` 的模型使用 128 输出 token 上限；其余保留 512，给推理和结果留空间。输出上限不等于必然消费；不把 incomplete 或换模计为原模型健康。

这是当前凭据与短请求的连通性和工具契约检查，不能证明大上下文、图片、长任务或未来持续可用；不会自动启用每周探测或修改路由策略。
