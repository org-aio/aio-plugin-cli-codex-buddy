# Deterministic command dispatch

`resolveDispatch(text, cwd)` is a headless intent resolver. It returns a JSON tool recipe (`argv`, `cwd`, source, action), `clarify` with candidates, or `llm` with a reason. No provider configuration or model request is involved. Phrase matching is closed and deterministic; project commands come from bounded manifest discovery. Git writes, shell expressions, arbitrary flags, mixed requests and ambiguous entries remain outside this fast path.

`model.mjs` owns the contract/defaults; `phrases.mjs` owns common utterances; `resolve.mjs` resolves context; `command.mjs` quotes the POSIX adapter; `bridge.mjs` handles native RPC lifecycle; `execute.mjs` supervises the owned POSIX process group, including package-manager children, when the native caller exits or is killed. Deliberately daemonized descendants that leave that process group are outside its ownership. Add phrases to a known action rather than mapping broad keyword hits to arbitrary shell text. New tool kinds should produce structured recipes and implement their own context/precondition checks.

The desktop adapter uses native `thread/shellCommand`, preserving the server's command/output/exit status and durable shell turn. The original short phrase is a quoted command comment. It neither inserts fake assistant success nor calls a model. Because this native method is unsandboxed, the adapter requires a confirmed local full-access/never-approval thread, no active turn, normal mode, compatible turn settings, and a POSIX host. Missing evidence uses ordinary routing. A settings update invalidates cached permission evidence until the server returns confirmed thread permissions again (for example, on resume). No retry/replay after native execution is submitted. A nonzero command exit remains a failure even if the containing native turn completes.

`router match` previews local resolution only; `router dispatch on|off|status` controls eligible desktop turns. Long-running commands remain native foreground operations (one-hour default timeout, configurable 1000–3600000 ms); interruption is native, and an active process is not proof of application/browser readiness. No auto-fix, browser opening, approval bypass, or background daemon lifecycle is implied.
